# 平渡展陈 · 易读展签复验

把同一位观众对旧版和易读样张的两次测读连成一对，供展陈主管在付印前复核。

## 工作现场

模拟客户是平渡展陈的六人设计与观众研究组，为二厅青釉器常设展试印说明牌。现场引导员分配读序并口头提问，分析员从纸质记录抄到表格，展陈主管以前要在聊天记录中追问结论对应哪份稿。最常见的差错是漏测被记成失败、把同一观众当成两份独立样本，以及样本更正后表格结论和会签意见错配。

上游交付展签原文、字号、行距、测读题和匿名结果。本应用登记版本、保留缺测、按读序核对配对样本并计算差值，主管签署后由二厅物料负责人下载会签结论与复验快照。

| 登录名 | 角色 | 页面和权限 |
|---|---|---|
| `analyst` | 分析员 · 沈砚 | 登记展签和批次，录入、修改配对，提交运行和导出结果，生成合并名单，查看会签 |
| `curator` | 展陈主管 · 许禾 | 查阅展签、样本、运行与合并名单，对当前样本签署发布或退回复测，导出结论 |
| `viewer` | 观察员 · 周简 | 查阅展签和匿名配对，查看并导出已发布运行与合并名单 |

本地演示密码统一为 `Proof5203!`。样本中只使用观众编号。

## 一次印前复验

1. 09:00，沈砚从 `YA-01_图录版.pdf` 和 `YA-02_易读样张.pdf` 两份模拟校样抄录文案。青釉刻划纹执壶的字号由 16 pt 改为 24 pt，行距由 1.35 增至 1.60。原稿和改稿在版本对照页并列显示。
2. 09:15，建立 `PD-1121` 批次。两次阅读共用判定题「花纹是在上釉前还是上釉后刻出的？」答「上釉前」记成功。
3. 10:00，将 `PD-01` 至 `PD-36` 交替分配读序，先读旧版、先读样张各 18 人。两段测读分别记录成功、未成功或缺测。
4. 11:00，在配对记录筛出 `PD-35` 的旧版缺测及 `PD-36` 的样张缺测。其余 34 对完整，每个读序各 17 对。
5. 11:15，沈砚在复验分析选择 95% 方向区间并提交 R1 样本。Worker 固定 36 条记录、两份展签和参数，产出复验结果。
6. 11:20，对照四格表。均成功 16 对、旧版独胜 2 对、样张独胜 12 对、均未成功 4 对。旧版 18/34（52.9%），样张 28/34（82.4%），配对成功率提高 29.4 个百分点。
7. 14:00，许禾复核 `p = 0.012939453125`、样张独胜占不一致对 `12/14`，95% 精确方向区间 `57.2%–98.2%`，并写明仅发布二厅 `YA-02` 付印方案。
8. 14:15，周简在已发布结论下载 `proof-<运行号>.json` 和 `proof-<运行号>-pairs.csv`。两份文件的样本修订号与 SHA-256 一致。补录缺测后形成新修订，旧快照仍可追溯。
9. 次日 10:00，两批复验一起复验：`PD-1121` 与 `PD-1122`（`YA-03`/`YA-04`）各选一次已完成的复验。两个批次测的是同一批 `PD-01`–`PD-36`，各有 34 对完整、每读序 17 人，观众池完全重叠。只有两次都测到的观众可以入组，每人只进一批。沈砚在合并名单页生成名单：每批先读旧版、先读样张各 8 人，两批共 32 人，两批之间没有重复观众。页面说明人数为什么停在 8：若每读序要 9 人，两批的先读旧版位置共需 18 位不同观众，合计只有 17 位，`PD-1121` 与 `PD-1122` 在争用同一批人；整体观众池也只有 34 人，再多 1 人每读序就要多 4 位新观众。
10. 次日 10:20，周简下载 `roster-<名单号>.json` 和 `roster-<名单号>.csv`，每行带`批次`与`来源复验`，可查回每人出自哪次复验。用同一批复验再生成不会新增名单；补录后某批的样本修订变了，须换用该批的新复验重算，才会形成新名单。

演示 seed 预置步骤 1–4 的批次、版本和配对（两个批次共 72 条配对），尚无运行、会签和名单。校样文件名用于描述现场来源，应用存储文案及排版参数。

## 计算与会签口径

- 完整配对要求旧版与样张结果均有观测。记 `n` 为完整对数、`b` 为旧版独胜、`c` 为样张独胜。两份成功率使用共同分母 `n`，差值为 `100 × (c − b) / n` 个百分点。
- McNemar 双侧精确检验使用 `m=b+c` 个不一致对。在等边际成功率原假设下，`X ~ Binom(m, 0.5)`，`p = min(1, 2 × Pr[X ≤ min(b, c)])`。存在完整配对且 `m=0` 时 `p=1`。
- 方向参数是在不一致对中样张独胜的条件概率，点估计为 `c/m`。Clopper–Pearson 等尾区间分别反演 `Pr[X ≥ c] = α/2` 和 `Pr[X ≤ c] = α/2`，其中 `α=1−置信水平`，边界 `c=0`、`c=m` 分别取下界 0、上界 1。`m=0` 时方向区间为空。`n=0` 时成功率、差值和 p 值均为空。
- 读序诊断分别输出登记、完整、缺失和成功率差值。完整配对口径受缺失机制影响。演示数据用于说明流程，测读结果不外推到其他展品或观众群。
- 版本、测读标准、按观众编号排序的配对、修订号、置信水平和方法版本共同进入 UTF-8 固定键序的 JSON 快照并生成 SHA-256。Worker 在事务中认领任务并复核校验值，进程意外退出会回滚认领，计算错误会记录失败状态。完全相同的成功或排队输入复用运行。变更读序、结果或置信水平会形成新输入。
- 主管只能签署当前样本修订的已完成运行。无完整配对只能退回复测。每个样本修订只能发布一份运行。有结论的历史运行保留原意见和快照。写入和分析状态变化会留审计事件。

## 合并名单口径

几批展签一起复验时，每批选一次已完成的复验运行。只有该运行快照里旧版与样张结果均有观测的观众可以入组；同一观众最多进一批；每批先读旧版与先读样张同为 `k` 人，取各批能同时达到的最大 `k`。取人数与观众答对与否无关，缺测的人不参与。

- 最大 `k` 用二分加最大流判定（`backend/src/services/allocation.py`，Dinic）。流网络中观众节点容量 1，每批的两个读序各连一个需求为 `k` 的槽位，可行当且仅当满流。
- 同样多人时用最小费用流打破平局：留在上一份名单的原批次代价 0，换批次代价高于任何一次保留，新人选再高一级。因此先尽量把上一份名单上的人留在原批次，再尽量多保留上一份名单的人。页面的「保留上一份名单的批次」用于指定参照名单；只有覆盖所选全部批次的上一份名单才能作为参照。
- 人数上不去时给出原因。`shortage` 指出某批在单个读序里可选的人不足 `k+1`；`shared_pool` 给出一个最小的批次与读序组合，它们的可选观众并集小于 `k+1` 乘以槽位数，即这些批次在争用同一批人；`pool_bound` 说明全部批次合计观众已用尽；`stale` 提示某批样本已更新、所选运行不是最新修订。
- 输入校验值覆盖所选运行、其快照中的完整配对与最终入选名单。只要落在同一份名单（同样的观众进同样的批次）即视为同一份，重跑只返回原名单（HTTP 200），不会新增；换了源复验或选出不同的人才会形成新名单。数据库对校验值唯一约束，服务端并在事务内加锁避免并发重复写入。
- 名单 JSON 与 CSV（`/api/rosters/{id}/export.json`、`/members.csv`）逐行带批次、来源运行号与运行修订，可查回每位观众来自哪次复验。

## 启动及本地开发

```sh
cp .env.example .env
docker compose config --quiet
docker compose up --build -d --wait
docker compose exec -T backend python -m scripts.seed_demo
```

浏览器打开 `http://127.0.0.1:18272`，API 文档在 `http://127.0.0.1:19272/docs`。PostgreSQL 端口为 `17772`。开发时可改 `frontend/src/` 后重新构建 `frontend`，改 Python 后重新构建 `backend` 和 `worker`。`docker compose down` 保留数据库。需要清空模拟样本时用 `docker compose down -v --remove-orphans`。

| 服务 | 技术和职责 |
|---|---|
| frontend | Nginx 1.27、原生 HTML/CSS/ES Modules。同源代理 `/api` |
| backend | Python 3.11、FastAPI、psycopg。JWT 会话、版本、样本、会签与导出 |
| worker | Python 3.11。PostgreSQL 持久队列，事务化计算，Redis 心跳 |
| db | PostgreSQL 16。业务数据、快照、运行与审计 |
| redis | Redis 7。带过期时间的 Worker 心跳 |

端口均绑定 `127.0.0.1`。`COMPOSE_PROJECT_NAME` 默认为 `label-readability`，`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 可覆盖端口，`NETWORK_SUBNET` 默认 `10.221.203.0/24`，`POSTGRES_PASSWORD` 与 `JWT_SECRET` 提供本地配置，`SEED_DEMO` 控制启动是否导入模拟数据。数据库和 Redis 使用命名卷。Compose 预留后端及 Worker 共享产物卷，现有 JSON 和 CSV 从记录实时生成。真实使用时须配置独立密钥、数据库密码与账户，演示账号只用于本机模拟。数据库迁移由后端启动时执行。

`backend/src/` 按路由、控制层、服务、输入模型、连接、中间件和枚举划分。`backend/migrations/` 存数据库迁移，`backend/scripts/` 存迁移入口与幂等 seed。`backend/tests/` 存标准库 unittest：`test_allocation.py`、`test_tiebreak.py` 与穷举结果比对，`test_rosters_integration.py` 需要可用的 `DATABASE_URL`，否则自动跳过。`frontend/src/` 按 API、状态、路由、页面、共享组件、常量和工具拆分。批次的脚本、运行日志及截图在独立验收目录。Noto Serif SC 与 Noto Sans SC 为本地字形子集，附 SIL Open Font License。补录内容若含子集之外的字形，由浏览器选用可用的中文字体。

| `analyst` / `curator` / `viewer` | Python `constants/enums.py`、凭据和授权控制、数据库账户约束。JS `constants/enums.js`、导航身份、写入控件与会签页 |

| `queued` / `succeeded` / `failed` | Python `constants/enums.py`、数据库运行约束、worker、队列及会签服务。JS `constants/enums.js`、运行列表、轮询与结果页 |
| `publish` / `revise` | Python `constants/enums.py`、输入校验、数据库会签约束与访问判断。JS `constants/enums.js`、运行状态与主管会签 |

## 已知范围

每批最多 1,000 对。样本通过页面逐条录入和修订，导出提供 JSON 及独立样本 CSV。页面呈现展签相对字号与行距供复核，实际物料尺寸和字体打样由设计组确认。反平衡顺序由现场执行，页面报告实际分配和缺失。会签为工作台内的发布记录。合并名单一次最多 12 个批次，超过 8 批时「争用同一批人」的说明改用残余网络给出最小批次组而非穷举。
